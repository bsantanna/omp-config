# Endpoint env vars — design

## Intent
Make the btech endpoints overridable per machine via env vars, defaulting to
today's values, so the repo isn't tied to one gateway/Langfuse host. Also
bring the README in line with the removed `GLM-5.3-Flash-EXL3` model override.

## Scope
- In: `agent/models.yml` `baseUrl`, `agent/mcp.json` `url`, `import.sh`,
  `export.sh`, `.env.example` (generated by export.sh), README.
- Out (non-goals): default model id in `config.yml`; vendored skill links.
- Anti-goal: any change in behavior when no env var is set.

## Constraint (verified)
- pi-mcp-adapter expands `${VAR:-default}` in MCP server URLs at runtime.
- omp does **not** expand env vars in `models.yml` `baseUrl` (tested with
  `${VAR:-default}` and bare name against a local listener; only a literal
  URL produced a request).

## Approaches
1. **Hybrid (picked):** runtime `${…:-default}` for mcp.json; import-time
   placeholder for models.yml. Keeps live override where the tool supports it.
2. Import-time placeholders for both: uniform, but loses runtime override for
   the Langfuse URL.
3. Runtime for both: impossible — omp doesn't interpolate `baseUrl`.

## Design
| Var | Default | Where | Mechanism |
|---|---|---|---|
| `LAN_LLM_BASE_URL` | `https://llm-gw-eu.btech.software/v1` | models.yml | repo stores `__LAN_LLM_BASE_URL__`; import.sh renders |
| `LANGFUSE_MCP_URL` | `https://langfuse.btech.software/api/public/mcp` | mcp.json | repo stores `${LANGFUSE_MCP_URL:-<default>}`; adapter resolves at runtime |

- **import.sh**: resolve `LAN_LLM_BASE_URL` = process env → `agent/.env` entry
  in target → default; literal-replace the placeholder (perl, no regex);
  self-check fails if the placeholder survives. No prompting for URLs.
- **export.sh**: rewrite `baseUrl:` value → `__LAN_LLM_BASE_URL__`; rewrite
  mcp.json `"url": "<anything not starting ${>"` → `${LANGFUSE_MCP_URL:-<default>}`
  (the default stays the btech URL, constant in the script); abort if either
  rewrite didn't land. `.env.example` gains both vars, commented, with defaults.
- **README**: document both vars (what travels, load examples, a short
  "Endpoints" note on the runtime vs import-time difference); replace the
  `GLM-5.3-Flash-EXL3, 1M context window` verify comment and any other
  model-override mention.

## Left to the builder
- Exact README wording; whether the default URL constants live at the top of
  each script (my call: yes, as `DEFAULT_*` vars).
- Verification: run export.sh against a temp omp home and import.sh into
  another, check rendered output with and without the env vars set.
